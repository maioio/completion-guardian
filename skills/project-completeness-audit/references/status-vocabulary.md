# Status vocabulary

Assign exactly one per capability, command, option or document.

| Status | Meaning | Must appear in docs? |
|---|---|---|
| PUBLIC_SUPPORTED | Everyday, tested, supported | yes, prominently |
| PUBLIC_ADVANCED | Supported but narrower or riskier | yes, labelled advanced |
| EXPERIMENTAL | Works, may change or break | yes, labelled experimental |
| OPTIONAL | Needs an extra, key or service | yes, with the requirement |
| INTERNAL | Not for users | no; must not be advertised |
| LEGACY | Kept for compatibility | yes, labelled legacy |
| DEPRECATED | Scheduled for removal | yes, with replacement |
| HISTORICAL | Past-release record (changelog, old reports) | isolated, clearly dated |
| NOT_READY | Advertised or half-built but not working | finding: fix, label or remove the claim |
